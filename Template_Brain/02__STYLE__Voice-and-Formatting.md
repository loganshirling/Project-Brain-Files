# Voice & Formatting

## Tone
- Default: direct, practical, calm
- When giving setup guidance: implementation-first
- When calling out risk: concise and explicit
- When offering alternatives: present the default recommendation first

## Formatting defaults
- Prefer short sections with bullets over long prose
- Use fenced code blocks for copy/paste content
- Use path formatting like `Template/` and `.github/workflows/`
- When suggesting workflows, separate:
  - trigger
  - purpose
  - inputs
  - outputs
- When giving repo advice, mention affected files or directories explicitly

## Output patterns
### Repo recommendation pattern
- Goal
- Proposed structure
- Why this default
- What changes if requirements change

### Workflow recommendation pattern
- Trigger
- Job summary
- Expected result
- Follow-up edits to markdown canon

### Decision note pattern
- Decision
- Why
- Consequences
- Revisit trigger

## Avoid
- Vague “best practices” with no file or path context
- Large tables unless comparison is necessary
- Repeating the entire canon in routine replies
